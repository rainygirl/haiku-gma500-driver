# Haiku 用 GMA500 ドライバー

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md)

Sony VAIO P のような Intel SCH US15W (Poulsbo、いわゆる「GMA500」) を搭載した
マシン向けのグラフィックドライバーです。このチップで Haiku が
**ハードウェアカーソル**を使えるようにします。VESA ドライバーではできないことです。

これがないと、app_server はマウスポインターをソフトウェアで描きます。動くたびに
ポインターの下を保存し、ポインターを描き、元のピクセルを戻します。2D
アクセラレーションのない 1.33 GHz Atom では、その処理が目に見えます。このドライバー
では表示エンジンがスキャンアウト時にポインターを合成するため、その処理自体が
なくなります。

## pkgman でインストール

| Haiku | コマンド |
| --- | --- |
| 32 ビット x86 (x86_gcc2) | `pkgman add-repo https://pkgman.rainygirl.com/x86_gcc2`<br>`pkgman install gma500` |

**インストール後は再起動してください。** カーネルはグラフィックドライバーを起動時に
読み込むため、再起動するまで何も変わりません。

`pkgman add-repo` が `Operation not supported` で失敗する場合、そのイメージの
ネットワークキットに TLS がありません。`http://pkgman.rainygirl.com/x86_gcc2` を
使ってください。

## ソースからインストール

Haiku マシン上で:

```sh
make                      # ドライバーと accelerant をビルド
make install              # 両方を ~/config/non-packaged にインストール
```

そのあと再起動します。

```sh
make uninstall            # 両方を削除。再起動すると VESA に戻ります
```

## 動いているかの確認

再起動後:

```sh
ls /dev/graphics/
```

`vesa` の隣に `poulsbo` があるはずです。app_server がどちらを選んだかは:

```sh
listimage $(ps | grep [a]pp_server | head -1 | awk '{print $2}') | grep accelerant
```

`poulsbo.accelerant` と出れば成功です。`vesa.accelerant` と出た場合はドライバーが
選ばれていません - [AGENTS.md](AGENTS.md) を参照してください。

## VESA に戻す

pkgman でインストールした場合:

```sh
pkgman uninstall gma500
```

ソースからインストールした場合:

```sh
make uninstall
```

いずれの場合も再起動してください。`/dev/graphics/poulsbo` が無くなると app_server
は自動的に VESA ドライバーへ戻るため、ドライバーが壊れても画面が出なくなることは
ありません。万一そうなったら ssh で入ってファイルを削除してください。

## 2D アクセラレーションについて

このドライバーはチップに載っている PowerVR SGX535 の 2D エンジンを動かし、画面間
コピーと矩形の塗りつぶし・反転のフックを提供します。VAIO P で測ったところ、コピーは
CPU が同じ処理をする場合より約 13 倍高速でした。

ただし Haiku の app_server はこれらのフックを呼びません。これはドライバー側で
どうにかできる話ではありません。`AccelerantHWInterface` は常にメインメモリー上に
バックバッファーを確保するため、app_server は各フレームをそこで合成し、仕上がった
矩形だけを画面へ送り出します。つまりブリットフックが肩代わりできる唯一の処理、
フレームバッファー内でのコピー自体を行いません。VAIO P で測ると 800x500 のウィンドウ
移動 1 ステップはバックバッファー内のコピー 2.4 ms と画面への転送 1.6 ms で、同じ
コピーを 2D エンジンで行うと 4.1 ms です。キャッシュの効くほうが既に高速です。

それでもフックを残しているのは、実装が正しく費用もかからず、この accelerant を直接
呼ぶ側では利用できるからです。測定値の詳細は [AGENTS.md](AGENTS.md) にあります。

## スプライトプレーン

このチップにオーバーレイプレーンはありません。Intel SCH US15W のデータシートは
プレーンとして Display、Cursor、VGA の三つだけを挙げ、overlay という語を一度も
使っていません。代わりにスプライトプレーンがあり、このドライバーはそれを Haiku
のオーバーレイフックとして提供します。表示エンジンが合成する二枚目の RGB 面で、
画面上の任意の位置に置けます。

YUV 変換も拡大縮小もありません。このチップの表示プレーンは RGB 専用で、ソースを
1:1 で出します。また Haiku のオーバーレイ経路自体がピクセルバッファーを
アプリケーションへ正しく渡せない状態のため、それが直るまではアプリから利用でき
ません。[AGENTS.md](AGENTS.md) を参照してください。

## このドライバーがしないこと

- **3D アクセラレーションはありません。** SGX535 の 3D 側には公開された資料が
  ありません。
- **モード設定を行いません。** BIOS が設定したモードをそのまま使います。対象の
  マシンはいずれもパネル解像度が固定です。
- **DPMS は「オン」のみ報告します。**
